# Что умеет elite-hud

Составлено по коду, не по памяти. Версия на момент составления: 0.11.1.

---

## 1. Строка HUD (верхняя) — постоянная сводка

| Сегмент | Что показывает | Источник |
|---|---|---|
| `carrier` | отсчёт до прыжка флотоносца и целевая система — только если прыжок запланирован; «готов через 04:12» во время перезарядки | `CarrierJumpRequest.DepartureTime`, `CarrierJump` |
| `system` | имя системы и число тел | `FSDJump`, `Location`, `Scan` |
| `balance` | баланс кредитов; зелёным, пока файл его обновляет | `Status.json` → `Balance`, откат на `LoadGame.Credits` |
| `ship` | **модель** корабля (Caspian Explorer, Panther Clipper Mk II) и дальность прыжка: макс и текущая с грузом | `Loadout`, выученные названия, формула дальности |
| `cargo` | занято/всего в тоннах, краснеет при полном трюме | `Loadout.CargoCapacity` + живое `Status.json` → `Cargo` |
| `missions` | взято миссий из лимита | `Missions`, `MissionAccepted` и т. д. |

Выключены, но доступны через конфиг или трей: `fss` (прогресс FSS),
`bio` (биологические сигналы).

## 2. Строка HUD (нижняя) — цель прыжка и флотоносцы

| Сегмент | Что показывает |
|---|---|
| `next` | следующая система, класс звезды, остаток прыжков |
| `carriers` | по сегменту на каждый носитель: позывной, **фактически загруженный груз** (`Cargo`) и зарезервированное место (`CargoSpaceReserved`), если оно не ноль: `V3G-N1H груз 7001/25000 т · бронь 12857`. **Иконка зелёная при доступе для всех, оранжевая при ограниченном** |

Выключен, но доступен: `mode` (режим игры), `crime` (штрафы и «Плохая
репутация»).

Свободное место (`FreeSpace`) больше не показывается как загрузка: покупка
резервирует место сразу, поэтому контракт на 20000 т читался как «20000 т уже на
борту». `SpaceUsage` сходится точно — `Cargo` + `CargoSpaceReserved` +
`FreeSpace` + `Crew` = `TotalCapacity`.

## 3. Строка EDSM о цели прыжка

Пока цель выбрана, под нижней строкой идёт то, что о системе знает EDSM — **до**
прыжка, а не после.

| Что | Источник |
|---|---|
| `открыта: <командир> <дата>` | `api-system-v1/traffic` → `discovery` |
| `заправка: да/нет` | `api-v1/system` → `primaryStar.isScoopable` (зелёный / оранжевый) |
| `трафик: сутки N, неделя N, всего N` | `api-system-v1/traffic` → `traffic` |
| `в EDSM нет данных — возможно, не посещалась` | `api-v1/system` вернул пустой список |

Запросы идут в фоновом потоке, по одному на систему (кэш в памяти сессии),
оверлей не ждёт. Сбой запроса — это не ответ: строка остаётся пустой, а система
не кэшируется, чтобы следующая попытка её спросила. Месяца и года в API нет.
По прибытии система перепроверяется (`edsm.verify_on_arrival`).

## 4. Строка подбора материалов

Одна строка под нижней строкой, живёт `materials.display_seconds` секунд и
исчезает сама. Ни звука, ни рамки, ни складывания в «xN» — уведомлений в проекте
больше нет, и это единственное, что осталось.

| Событие | Что показывает |
|---|---|
| `MaterialCollected` | «+1 Сера (Редкость: 1)  Всего: 285» |

Название берётся из `Name_Localised`, поэтому язык клиента соблюдается без
переводов в проекте. Редкость — из таблицы `elite_hud/data/materials.json`.
«Всего» появляется только после события `Materials` (оно сообщает трюм целиком
при входе в игру): до него итог неизвестен, а не равен единице.

Трюм материалов ведут также `MaterialDiscarded`, `MaterialTrade`, `Synthesis` и
`EngineeringCraft`.

## 5. Меню в трее

* **Показать / скрыть HUD**
* **Открыть config.toml**
* **config: <путь>** — какой файл используется, и доступен ли он для записи
* **Верхняя строка** и **Нижняя строка**: галочка на каждый блок
* **Монитор**: на каком экране показывать
* **Режим обновлений** и проверка обновлений
* **Выход**

Изменение, которое не удалось записать в `config.toml`, сопровождается
предупреждением в трее с путём: галка уже переключилась и HUD уже изменился,
поэтому молчаливый отказ выглядел как успех до следующего запуска.

## 6. Обновление

Проверка GitHub Releases, автоматическая или по запросу загрузка, установка
тихим запуском установщика для установленной копии и распаковка для портативной.
Проверка SHA-256 перед установкой.

## 7. Командная строка

`--replay`, `--speed`, `--replay-loop`, `--replay-live`, `--headless`,
`--print-state`, `--make-config`, `--check-update`, `--carrier-report`,
`--self-check`, `--force`, `--verbose`, `--journal-dir`, `--config`, `--version`.

## 8. Конфигурация

Разделы: `[journal]`, `[overlay]`, `[materials]`, `[edsm]`, `[carrier]`,
`[commander]`, `[update]`, `[logging]`, `[overlay.labels]`.

Новый файл всегда создаётся в `%APPDATA%\elite-hud\config.toml`, а не рядом с
программой: каталог установки принадлежит установщику, и настройки в нём теряются
при обновлении. Файл рядом принимается, если он уже есть — так работает
намеренно портативная копия.

Недостающие секции дописываются при запуске, комментарии и значения не трогаются.
`[overlay.labels]` намеренно никогда не пишется в файл: это заготовка для
локализации, и файл с полным набором одного языка переопределял бы выбор языка
навсегда.

## 9. Данные

| Таблица | Источник | Примечание |
|---|---|---|
| `materials.json` | EDCD/FDevIDs | **только редкость**; имена берутся из журнала |

Названия кораблей и данные флотоносцев **изучаются из журнала** и кэшируются
рядом с конфигом — готовые таблицы не поставляются из-за лицензий.

## Чего сознательно нет

| Не сделано | Почему |
|---|---|
| Уведомления (экзобиология, первый след, звание, звук, рамка) | убраны по просьбе; остались строка подбора материалов и строка отказа в стыковке |
| Трафик EDSM за месяц и год | в API их нет: только сутки, неделя и всего |
| Материалы на ногах (Odyssey) как уведомления | журнал не пишет событие подбора: за 5 дней 2 события `Backpack` и 1005 `ShipLocker`, и тот меняет только расходники |
| Прогресс ранга Империи/Федерации в реальном времени | `Rank` и `Progress` игра пишет только при входе в игру |
| Кредитовая оценка непроданной картографии | журнал не сообщает стоимость скана, а формула выплаты не подтверждена |
| Редкость Тааргоидских материалов | их нет в таблице FDevIDs |
| Оверлей поверх эксклюзивного полного экрана | невозможно технически |
| Тихий запрос UAC при обновлении | установка в `Program Files` требует прав |

## Что не проверено на живых данных

* **Отображение на экране после правок строки** — Qt-тесты идут только в CI, а
  машина, на которой писался код, Qt запустить не может. Поэтому в CI добавлен
  `tools/smoke_run.py`: он поднимает оверлей целиком и падает, если тот выходит
  или пишет traceback.
* **Резервирование места на флотоносце** — поле `CargoSpaceReserved` читается из
  журнала, а не выводится; в журналах этого проекта оно равно 12857 при
  контракте на покупку. Семантика взята из имени поля и из того, что
  `SpaceUsage` с ним сходится.
