# Что можно достать из журналов Elite Dangerous

Анализ построен на **ваших** журналах: 6 файлов `Journal.*.log` (14–16 сентября 2026,
9 462 события, 101 тип события, 4,0 МБ) плюс 7 сопутствующих JSON-файлов в той же папке.

Всё, что ниже, проверено на ваших данных — в колонке «Пример» стоят реальные значения
из ваших логов. Ничего не выдумано из документации.

---

## 1. Состав папки журналов

| Файл | Размер | Что внутри | Когда обновляется |

| `Journal.<дата>.<время>.<NN>.log` | 233 КБ – 1,2 МБ | События сессии, JSON Lines, по одному на строку | Дописывается постоянно |
| `Status.json` | 69 Б | Текущее состояние корабля | Несколько раз в секунду |
| `NavRoute.json` | 83 Б | Текущий проложенный маршрут | При прокладке/сбросе |
| `Market.json` | 136 КБ | Полный прайс-лист станции | При открытии рынка |
| `ShipLocker.json` | 743 Б | Инвентарь «на ногах» (Odyssey) | При изменении |
| `ModulesInfo.json` | 3,2 КБ | Энергопотребление и нагрев модулей | Периодически |
| `Outfitting.json` | 1,2 КБ | Ассортимент снаряжения станции | При открытии |
| `Shipyard.json` | 252 Б | Ассортимент верфей станции | При открытии |

### Важная тонкость про `Status.json`

В скопированной вами папке он весит 69 байт и содержит ровно:

```json
{"timestamp": "2026-09-16T23:59:49Z", "event": "Status", "Flags": 0}
```

Это **не** нормальный вид этого файла. Игра при выходе затирает его до минимума: эти 69
байт — то, что осталось после закрытия игры, а не то, что лежит там во время полёта.

Чего в нём не хватает — известно из официального Journal Manual v38, раздел 14 «Status
File» (стр. 95 из 109,
`https://hosting.zaonce.net/community/journal/v38/Journal_Manual_v38.pdf`): во время игры
заполнены `Fuel: {FuelMain, FuelReservoir}`, `Cargo`, `Balance`, `LegalState`, `Pips`,
`GuiFocus`, координаты и — что важнее всего для панели прыжка —
`Destination: {System, Body, Name}`, то есть текущая цель прокладки.

> **Оговорка.** Список полей взят из официального мануала, а не из вашей копии файла: в
> ней лежит уже затёртая версия, и проверить имена полей на ней нельзя. Мануал — источник
> надёжный, но перед задачей 7 стоит один раз взглянуть на файл при работающей игре.
> Специально отмечу: **дальности прыжка в `Status.json` нет** — это проверено отдельно
> четырьмя способами (мануал v38, EDDI, EDMC, `Lombra/elite-api-docs`), её надо считать
> самим. `JumpRangeCurr`/`JumpRangeMax` — это `CarrierStats`, дальность носителя, а не
> корабля; на этом легко ошибиться.

Практический вывод: `Status.json` надо читать живьём, а не по копии. Если `Destination`
там действительно есть, цель прыжка берётся оттуда и вычислять её самим не придётся.

## 2. Что даёт журнал по категориям

Легенда колонки «Покрытие»: ✅ данные есть всегда · ⚠️ есть, но с оговоркой · ❌ в
журнале нет, нужен внешний источник.

59–64 с (медиана 62). Сейчас в конфиге `carrier.jump_cooldown_seconds = 290`.

Флотоносец у вас **эскадронный**: `CarrierType: SquadronCarrier`, позывной `KSS0`,
название `Sergey Korolev - mHQ`, баланс 10 571 031 484 КР. Это важно для HUD — личный
носитель может выглядеть иначе.

| Что | Событие и поля | Ваши данные | Покрытие |

Про `Promotion` важная деталь: в ваших логах есть только `Empire` и `Exobiologist`, и
лежит там **новый** индекс звания. Событие приходит в момент повышения, тогда как
`Rank` пишется только на старте сессии. Если не обновлять сохранённый ранг по
`Promotion`, HUD до перезапуска будет показывать старое звание — эту ошибку я уже
исправил.

Ещё: `Progress == 100` **не** означает «максимум». На нулевом ранге супердержавы
командир может стоять на 100 % и ждать миссии на повышение. Проверять надо индекс по
таблице.

### 2.8 Состояние корабля и прыжок

| Что | Событие и поля | Ваши данные | Покрытие |
|---|---|---|---|
| Полная загрузка | `Loadout` → `MaxJumpRange`, `FuelCapacity`, `CargoCapacity`, `Modules[]`, `Rebuy` | 25 событий | ✅ |
| Заправка | `FuelScoop` → `Total`, `RefuelAll` → `Amount` | 109 / 50 | ✅ |
| Техника и костюм | `SuitLoadout`, `Backpack`, `ShipLocker.json` | 29 / 29 | ✅ |
| Энергия и нагрев | `ModulesInfo.json` | 3,2 КБ | ✅ |
| Целостность | `HullDamage`, `ShieldState`, `Repair`, `RepairAll` | 1 / 5 / 3 / 5 | ✅ |
| **Дальность с грузом** | считается по формуле игры | — | ⚠️ |
| **Дальность в `Status.json`** | её там нет вообще | — | ❌ |

Про дальность. `MaxJumpRange` в `Loadout` — это «пустой корабль и топлива ровно на один
прыжок». Реальную дальность с грузом игра не пишет нигде, её надо считать:

```
дальность = оптимальнаяМасса / масса × (топливо × 1000 / linearConstant) ^ (1 / powerConstant)
масса = сухаяМасса + топливо + груз
```

Я это реализовал и проверил не сам на себе, а против игры: для четырёх ваших кораблей
формула воспроизводит написанный игрой `MaxJumpRange` с расхождением **5,4e-06 ly**.
Ваша Mandalay с полным баком 48 т даёт 65,6 ly против максимума 72,9, а с 64 т груза —
57,3 ly.

## 3. Чего в журнале нет

Чтобы не строить планов на данных, которых не существует:

| Нужно | Где брать |
|---|---|
| Редкость материалов | таблица `EDCD/FDevIDs` |
| Базовая цена вида до продажи | своя таблица + `EDCD` |
| Лимит миссий (20) | константа в конфиге |
| Иконки рангов | нет в игре как файлы, нужны свои |
| Биосигналы системы (для панели EDSM) | Spansh `api/dump/<id64>` → `signals.genuses` |
| Первооткрыватель, трафик системы | EDSM `www.edsm.net/api-system-v1/traffic` |
| Цена продажи в другой системе | EDSM или Spansh, по сети |

Замечание по сетевым адресам, на которое я потратил время: **`api.edsm.net` не
существует** (NXDOMAIN), правильный хост — `www.edsm.net`. То же с `api.spansh.co.uk` →
`spansh.co.uk`. Это ломает большинство примеров, которые попадаются в интернете.

## 4. Язык и локализация

Ваша игра на русском, поэтому правило простое: **всюду, где есть символ, брать символ**.

```
Genus:           "$Codex_Ent_Bacterial_Genus_Name;"   ← ключ, не меняется
Genus_Localised: "Бактерии"                            ← подпись, зависит от языка
```

Локализованные поля полезны для показа, но категорически не годятся для логики: игрок
с английским клиентом получит `"Bacteria"` и ни один поиск по `"Бактерии"` не сработает.
Все наши таблицы индексированы по символам, локализация подставляется последним шагом.

Отдельный случай — `Rank` и `Progress`: у них **вообще нет** локализованных полей. Только
числа. Значит русские названия званий («Граф», «Уорент-офицер») обязаны быть нашей
таблицей, и это единственное место, где возможна ошибка в названии.

## 5. Итог

Журнал закрывает почти всё, что нужно для HUD, и закрывает надёжно — с привязкой к
символам, а не к подписям. Внешних источников требуют ровно пять вещей: цены
биовидов, редкость материалов, иконки рангов, и два сетевых справочника (EDSM и Spansh).
Задача 7 (панель прыжка) — единственная, которая без сети не работает вообще; всё
остальное можно сделать полностью офлайн.
